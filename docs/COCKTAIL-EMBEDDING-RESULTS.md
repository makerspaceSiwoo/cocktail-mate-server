## 512→32 결과

512차원 코사인 이웃을 기준으로 측정했다.

| 방식 | recall@5 | recall@10 | recall@15 |
| --- | ---: | ---: | ---: |
| 직접 학습한 32D 이웃 좌표 | **0.9385** | **0.9188** | **0.9642** |
| PCA 32D baseline | 0.6365 | 0.6578 | 0.6751 |

직접 학습 모델이 세 k에서 모두 PCA보다 크게 높다. 현재 카탈로그 관계 보존을
우선하는 transductive 축소이므로 신규 칵테일이 생기면 전체 32D 좌표를 함께
재학습한다.

## 3D 구 내부 vs 표면

두 방식 모두 32차원 추천 벡터에서 바로 이웃보존 축소했으며, 일반 유클리드
축소 결과를 점별 정규화해 표면에 붙이는 방식은 사용하지 않았다.

| 기준 공간 / 지표 | 구 내부 UMAP | 구면 직접 학습 |
| --- | ---: | ---: |
| 32D recall@5 | **0.4229** | 0.3196 |
| 32D recall@10 | **0.4012** | 0.2872 |
| 32D recall@15 | **0.3936** | 0.2779 |
| 32D stress | 0.3799 | **0.3237** |
| 512D recall@5 | **0.4176** | 0.3213 |

| 512D recall@15 | **0.3856** | 0.2724 |

512차원 PCA 상위 3성분의 설명 분산 비율은 `0.2934`다. 3차원 자체의 정보
병목이 크다는 뜻이며, 구면은 global distance stress가 조금 낮지만 추천 UX에
중요한 top-k 이웃 recall을 크게 잃는다.

### 정성 스팟체크: 플레이밍 닥터페퍼

- 512D와 학습 32D의 top-5는 5개 모두 일치했다.
- 구 내부 top-5는 512D top-5 중 2개를 유지했다.
- 구 표면 top-5도 이 사례에서는 2개를 유지했다.

## 결정

`ball`(구 내부)을 선택한다. 실제 추천 source of truth인 32D 공간의 recall@5가
표면보다 약 10.3%p 높기 때문이다. 선택 좌표는
`embedding-artifacts/embedding-3d-selected.*`에 생성됐다.

프론트는 이 좌표를 점별 L2 정규화하면 안 된다. 구 내부 결과의 반경 범위는
`0.0674~1.0`, 평균은 `0.4658`이며 반경도 이웃 배치에 사용하는 세 번째
자유도다. 시각 좌표는 추천 근거가 아니며 추천 API는 계속 32D pgvector 코사인
검색을 사용한다.

이 초기 결정의 32D embedding과 구 내부 3D 좌표는 DB 602개 행에 반영했다.

## 후속 실험: 클러스터 우선 구 표면

구 내부의 깊이 때문에 칵테일을 직접 찾기 어렵다는 UX 문제를 기준으로 실험을
바꿨다. 전체 거리 복원을 포기하고 정말 가까운 이웃과 군집만 보존한다.

- 군집: L2 정규화 32D의 K-means `k=7`
- 군집 크기: `118 / 113 / 103 / 80 / 69 / 61 / 58`
- 원본 32D 이웃의 같은 군집 잔존율: top-1 `80.07%`, top-3 `77.13%`,
  top-5 `75.65%`
- 군집별 로컬 배치: cosine UMAP `n_neighbors=3`
- 군집 관계: 32D centroid cosine 25% + 대칭 cross-cluster top-5 association 75%
- 구면 중심 배치: 관계 top-2 recall `1.0`, top-3 recall `0.9048`
- 군집 관계 거리와 구면 각도의 Spearman 상관: `0.7325`
- 중심 분산: 평균 중심 벡터 크기 `0.0616`, 평균 중심 각도 `101.1°`
- adaptive cap 반경: `45.8°~54.4°`, 최근접 중심 각도의 95%, 최대 `0.95 rad`
- 내부 분리: 최근접 점 각도 중앙값 `1.224° → 2.410°`, 하위 10% 값
  `0.341° → 0.782°`

| 32D 기준 | 구 내부 UMAP | 기존 구면 직접 학습 | 클러스터 구면 |
| --- | ---: | ---: | ---: |
| recall@1 | 0.2924 | **0.4003** | 0.3738 |
| recall@3 | **0.4186** | 0.3450 | 0.3942 |
| recall@5 | **0.4229** | 0.3196 | 0.3598 |
| recall@10 | **0.4012** | 0.2872 | 0.3125 |

7개 군집으로 세분화하면서 개별 top-k recall은 6개 버전보다 낮아졌지만, 군집
중심을 인위적인 동일 각도로 배치하던 문제를 제거했다. 가장 가까운 군집 쌍은
`48.2°`, 가장 먼 쌍은 `144.3°`로 줄였고, 평균은 `101.1°`다. 대신 로컬 UMAP의
`min_dist`와 robust 95-percentile cap scaling으로 군집 내부 최근접 점 간격을
약 두 배로 늘렸다. 이 시각적 분리와 겹침의 대가로 recall@5는 `0.3711`에서
`0.3598`로 `1.13%p` 감소했다. 추천 API는 계속 32D를 사용하므로 실제 추천
정확도에는 영향을 주지 않는다.

군집 안에서만 후보를 비교한 recall은 `@1 0.5000`, `@3 0.4684`,
`@5 0.4239`이다. 특히 가장 압축됐던 cluster 1의 최근접 점 중앙값은
`0.449° → 1.931°`로 커졌다. global stress `0.3270`는 먼 군집 간 거리를
복원하지 않는 이번
목적에서는 보조 지표로만 기록했다.

새 좌표는 `embedding-artifacts/embedding-3d-cluster-surface.*`에 생성했다. 기존
DB의 구 내부 좌표는 유지했으며, 클러스터 구면 좌표는 아직 DB에 반영하지 않았다.

## 후속 실험: 추천 집합 top-3 hit

실행일: 2026-08-03

512→32는 기존 학습 좌표를 그대로 유지하고 32→3D 배치만 다시 실험했다.
이번 주 지표는 거리값이나 순위가 아니라, 각 칵테일의 **3D 최근접 3개 안에
32D ANN 추천 5개가 하나라도 포함되는 비율**이다.

이 지표는 `recall@3`과 다르다. 예를 들어 추천 5개 중 하나만 3D 최근접 집합에
있어도 해당 칵테일은 hit로 계산한다. 602개 전체를 대상으로 동일하게 측정했다.

| 32D → 3D 배치 | 구 표면 | 1개 이상 포함 | 평균 포함 수 | 3개 모두 포함 | strict recall@3 |
| --- | :---: | ---: | ---: | ---: | ---: |
| **t-SNE 자유 3D** | 아니요 | **99.50%** (599/602) | **2.02/3** | **26.41%** | **56.59%** |
| UMAP 자유 3D | 아니요 | 95.85% (577/602) | 1.61/3 | 9.47% | 45.63% |
| 기존 클러스터 구면 | 예 | **92.19%** (555/602) | **1.45/3** | **6.31%** | 39.42% |
| t-SNE 구면 투영 | 예 | 90.86% (547/602) | 1.42/3 | 6.15% | **41.25%** |

선택 기준은 32D 추천 집합 any-hit, 평균 포함 수, 3개 모두 포함, strict
`recall@3` 순이다. 최선 설정은 다음과 같다.

- t-SNE 자유 3D: `perplexity=8`, `early_exaggeration=4`,
  `seed=20260803`
- UMAP 자유 3D: `n_neighbors=3`, `min_dist=0.2`, `seed=20260803`
- t-SNE 구면 투영: `perplexity=3`, `early_exaggeration=4`,
  `seed=20260803`

이 hit 기준의 전체 최고는 t-SNE 자유 3D다. 모든 점을 구 표면에 둬야 한다면
기존 클러스터 구면이 t-SNE 구면 투영보다 any-hit에서 `1.33%p` 높다. 반면
동일 크기 top-3 집합의 평균 교집합은 t-SNE 구면 투영이 더 높다. 따라서
시각화 좌표의 선택은 `최소 한 개의 추천 발견`과 `top-3 전체 복원` 중 어느
목표를 우선하는지에 따라 달라진다.

추천 API의 source of truth는 계속 32D ANN이며, 이 실험은 DB를 변경하지 않았다.
